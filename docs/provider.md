## Prospective observation

The public comparison shortlist stores the two selected wallet identities and their dated ranking rows in this browser for each ranking period. Opening rankings or switching periods restores those selections without reading either wallet. A comparison requests one positions page per wallet and labels its coverage. Saved rank, P/L and volume refer to the original provider read time for that wallet. The shortlist remains available when a new ranking read fails. Remove an address from the shortlist on any page to replace it. A buy check belongs to the current visit and retains its own simulated budget and window.

Run this from the repository root on a Linux host with authorized access to the public Data API and CLOB. The example uses the wallet in the upstream SDK fixture. Replace it with the public trading wallet to observe.

```sh
python3 -m apps.server.observe 0x7c3db723f1d4d8cb9c550095203b686cb11e5c6b --seconds 10
```

The CLI fixes a 1–30 second UTC window beginning at the next whole second, then reads one page of new BUY activity. An optional `--index-wait N` delays that single read by 0–300 additional seconds to test late indexing without changing the window. The receipt counts returned rows and ordinary wallet-relative BUYs and reports whether more pages exist. If a BUY is visible, the CLI selects the earliest eligible event on the returned page and immediately requests that token's book. A paginated response remains incomplete even when this pair is usable for research. An empty response can reflect indexing lag. Maximum two GETs, 256 KiB per response, four-second socket timeout, and a command deadline 12 seconds beyond the selected window and indexing wait.

JSON output records event time, local retrieval times, transaction, condition and token IDs, exact reported price and shares, provider book timestamp, minimum size and price tick when supplied, and the best three displayed asks. A matched book includes its signed age at detection (detection minus source time in milliseconds), and the best ask less the leader price in price units per share. These descriptive measurements include no queue, fee or actual fill evidence. The source-to-receipt difference includes the chosen sampling window and possible clock skew. `observed` means the matching book was requested after detection and its source timestamp is between detection and receipt. The activity response must also cover the full window. A previously updated book can still be unchanged, but a pre-detection timestamp gives incomplete timing evidence. Clock inconsistencies, empty asks, unsupported responses and endpoint failures produce partial or unavailable evidence. Exit code 0 covers observed and waiting states, and 2 covers incomplete or unavailable evidence.

**Activity-only identity.** The ordinary public activity model exposes a transaction hash. A transaction can contain multiple fills and overlapping representations. The probe leaves `fillId` null and emits no copy signal, order, fee estimate or modeled return. Connecting these observations to a prospective shadow decision requires a reliable participant-relative fill identity, instrument version, and follower costs. The checked SDK distinguishes normal trades from combos and reports ask levels in descending price order.
