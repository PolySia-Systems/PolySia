Checked 2026-11-25. All public reads identify PolySia and its project URL. The adapter uses documented HTTPS GETs with bounded response sizes, timeouts and no credentials, redirects or retries.

Each row retains its lifecycle, exact shares and identity checks. Cash, private orders, equity, closed and combo positions remain outside this read. |

## Prospective observation

Run this from the repository root on a Linux host with authorized access to the public Data API and CLOB. The example uses the wallet in the upstream SDK fixture. Replace it with the public trading wallet to observe.

```sh
python3 -m apps.server.observe 0x7c3db723f1d4d8cb9c550095203b686cb11e5c6b --seconds 10
```

The CLI fixes a 1–30 second UTC window beginning at the next whole second, then reads one page of new BUY activity. An optional `--index-wait N` delays that single read by 0–300 additional seconds to test late indexing without changing the window. If the page is complete and contains an ordinary wallet-relative BUY, the CLI selects the earliest reported event and immediately requests that token's book. A window containing more than 20 rows is incomplete. An empty response can reflect indexing lag. Maximum two GETs, 256 KiB per response, four-second socket timeout, and a command deadline 12 seconds beyond the selected window and indexing wait.

JSON output records event time, local retrieval times, transaction, condition and token IDs, exact reported price and shares, provider book timestamp, minimum size and price tick when supplied, and the best three displayed asks. A matched book includes its signed age at detection (detection minus source time in milliseconds), and the best ask less the leader price in price units per share. These descriptive measurements include no queue, fee or actual fill evidence. The source-to-receipt difference includes the chosen sampling window and possible clock skew. `observed` means the matching book was requested after detection and its source timestamp is between detection and receipt. A previously updated book can still be unchanged, but a pre-detection timestamp gives incomplete timing evidence. Clock inconsistencies, empty asks, unsupported responses and endpoint failures produce partial or unavailable evidence. Exit code 0 covers observed and waiting states, and 2 covers incomplete or unavailable evidence.

**Execution identity remains unresolved.** The ordinary public activity model exposes a transaction hash. A transaction can contain multiple fills and overlapping representations. The probe leaves `fillId` null and emits no copy signal, order, fee estimate or modeled return. Connecting these observations to a prospective shadow decision requires a reliable participant-relative fill identity, instrument version, and follower costs. The checked SDK distinguishes normal trades from combos and reports ask levels in descending price order. [Activity model](https://github.com/Polymarket/py-sdk/blob/81e8abfb2a131ef3874f8fe405c9d95b2123fcdf/src/polymarket/models/data/activity.py) · [Book model](https://github.com/Polymarket/py-sdk/blob/81e8abfb2a131ef3874f8fe405c9d95b2123fcdf/src/polymarket/models/clob/order_book.py) · [Book request](https://github.com/Polymarket/py-sdk/blob/81e8abfb2a131ef3874f8fe405c9d95b2123fcdf/src/polymarket/_internal/actions/clob.py)

On 2026-11-25 an initial one-second lookup was denied in cloud setup. After public connectivity was available, the same read completed and reported waiting. A separate direct token-matched CLOB read returned eight ask levels. This verifies response compatibility only.

For the prospective trial, we chose the most frequent BUY wallet in one public 100-trade page to increase the chance of observing activity. The selected wallet, `0xc69bd5567b40ef4d11922eaa57e1f9be1c642076`, accounted for ten BUY rows. The newest source timestamp in the selection page preceded retrieval by about 263 seconds. Each probe fixed its window before reading its trades. These samples share a wallet and market conditions.

- The first 30-second window exceeded the 20-row request budget and returned incomplete.
- In a four-second window the adapter observed a 5-share BUY at 0.002, then received the matching token/condition book 198 ms after detection. It showed a best ask of 0.002 for 113164.74 shares, a five-share minimum and 0.001 tick. The best displayed ask minus the leader price was 0.000 per share. The source timestamp preceded detection by 245 ms, so the receipt remains incomplete under the post-detection gate. The transaction reference is `0x2d01b38492b8ff2d672d784a6edacb7c3e5e96c1f9242e6a729d5959a3896614`.

- Another 30-second window included the four-second interval. Reading it after a deliberate 275-second indexing wait again exceeded the page budget. Increasing retrieval delay alone did not resolve the sampling limitation.

All three activity-window results were incomplete. One included a matched token book and none met the post-detection source-time gate. To test short-lived opportunities, the next experiment needs point-in-time book updates, stable participant-relative execution identity and applicable fees. No follower order, simulated return or live financial outcome was produced by these probes.
